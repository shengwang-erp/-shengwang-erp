# Task 04：仓库冻结成本连接项目成本

日期：2026-08-09
分支：`codex/warehouse-forward-port`
基线：`5192edf88ce0ecf4aad578969e9ef51abb26c15a`
范围：正式项目材料成本、零散工单材料成本与项目归属、内部领用排除、采购/仓库成本防双计、仓库项目成本保护。未包含退库、Task 5 页面、推送、部署或线上数据操作。

## 实现结果

- 正式项目出库只有在仓库负责人确认后才按实际 FIFO 批次冻结成本，生成唯一 `WAREHOUSE-SO:<stock-out-id>` 项目成本；重复确认零重复入账。
- 零散工单可先领料后归属项目，也可先归属再继续领料。项目成本使用唯一 `WAREHOUSE-MWO:<minor-work-order-id>` 记录，金额为全部已确认领料的冻结成本合计；同项目重复归属零变更，改归其他项目失败。
- 零散工单成本日期固定为工单 `work_date`。以后月份追加领料只增加金额，不会把历史成本整体移动到追加月份；真实创建、更新时间仍使用服务器审计时间。
- 内部领用只改变库存和仓库流水，不生成项目成本。
- 已确认采购到货仍保留在采购业务、应付和现金流中，但从项目利润的直接采购成本来源排除；项目利润只消费已确认仓库出库成本，避免同一材料重复计入。
- 仓库自动成本在通用项目成本页面只读。数据库触发器同时阻止非表所有者伪造、修改、逻辑删除、物理删除或截断仓库命名空间记录。
- 手工项目成本改为单条持久化：新增/修改只 `upsert` 当前手工记录，删除只软删除当前手工记录，不再把包含仓库自动成本的整个数组回写。
- 仓库成本采用固定 `1/10000` 日元单位校验和累计。`166.6667`、`0.1 + 0.2` 可准确进入会计月度汇总、首页、老板驾驶舱、项目累计成本与利润；采购和手工成本的原有整数校验没有放宽。
- 仓库成本上下文由数据库按当前活跃员工和两项读取权限生成；账号切换期间旧上下文不会跨账号复用，认证失效会退出登录。

## 数据库安全与原子性

- 项目成本写入由私有 `SECURITY DEFINER` helper 完成，固定 `search_path`，并验证活跃项目、活跃操作人、确定性记录键、来源单据、冻结金额上限和来源数组。
- 正式项目成本冲突会使本次出库确认的状态、FIFO 余额和库存流水整笔回滚。
- 零散工单的出库确认与项目归属使用相同 advisory-lock 命名空间及工单行锁顺序，避免并发丢失追加成本或死锁。
- 采购防双计上下文只认已经产生真实仓库批次的确认收货；确认后作废仍保留库存来源事实，待处理、拒绝和确认前作废不进入集合。
- 前端不能凭采购 payload 中自报字段决定是否排除成本。

- 跨月 RED：仓库工作流 `2/196` 失败，工单工作日 `2026-07-31` 的成本实际被写为确认日 `2026-08-09`。
- 固定点 RED：成本域 `0.1 + 0.2` 得到 `0.30000000000000004`；Dashboard 将 `166.6667` 判为 error；Home 将合法小数成本降级；零散工单合计同样漂移。最终审查又用 `1.0050` 证明直接乘 `10000` 会产生 `10049.999999999998` 并误拒绝合法值，现已改为规范四位十进制字符串加 BigInt 安全单位转换。
- 单条持久化 RED：仓库成本存在时，旧的 `saveList` 会尝试更新仓库受保护行并使手工项目成本保存失败。
