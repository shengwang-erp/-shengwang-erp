# 可配置收款计划设计

## 目标与范围

把固定的首期、中期、尾款三期计划改为按项目配置任意期数的收款计划，同时完整保留线上已有三期计划的 `planId`、金额、比例、日期和实际到账关联。只修改合同收入链路，不重构无关模块。

## 已核查的线上事实

- 线上有 1 个项目、3 条有效计划，阶段为 `initial`、`middle`、`final`。
- 线上有 1 笔有效实际到账，通过 `planId` 正确关联首期计划；无悬空关联。
- 线上写计划 RPC 为 `upsert_project_payment_plan_secure(p_payload jsonb)`，一次写一期；数据库只约束记录主键、`record_key` 唯一和状态值，没有计划金额、比例或到账关联约束。
- 当前浏览器端把三期阶段写死，并用 `Promise.all` 逐条保存，因此不具备整份计划原子性。

## 数据兼容

每一期继续使用稳定 `planId`。新记录增加：

- `installmentOrder`: 从 1 开始的连续整数；
- `name`: 可编辑期次名称；
- `allocationWeight`: 最多两位小数的非负比例；
- 保留现有 `plannedTaxInclusiveAmount`、`dueDate`、`remark` 和审计字段。

旧三期不批量改写：读取时把 `initial/middle/final` 映射为顺序 1/2/3 和名称“首期款/中期款/尾款”。用户以后保存该项目时，原 `planId` 不变，只补齐新字段。到账关联以 `planId` 为准；旧 `stage` 仅作为兼容快照，不再作为新计划身份。

## 计算规则

- 比例输入最多两位小数，并转成整数基点计算，`100% = 10000`，避免浮点误差。
- 新计划只有比例合计精确等于 100% 时才生成有效金额预览。
- 前 N-1 期按比例四舍五入到整数日元；最后一期金额等于合同计算基数减去前面金额合计，承接取整差额。
- 已关联有效到账的期次，其比例、计划金额和 `planId` 完全锁定，不能删除。
- 合同金额变化时不自动覆盖已确认计划；界面显示计划合计与新合同基数的差额。用户主动选择重新计算后，锁定期次保持不变，剩余合同金额按未收款期次的相对比例分配。
- 保存时比例合计必须为 100%，金额合计必须等于当前调整后税入合同金额。

## 原子保存与数据库保护

新增 `replace_project_payment_plan_secure(p_project_id text, p_plans jsonb)`：

1. 数据库重新核验在职账号、项目更新权限和项目财务查看权限；
2. 锁定项目、该项目计划及到账记录；
3. 数据库自行计算当前调整后税入合同金额；
4. 校验计划数组、连续顺序、唯一 ID、比例、整数日元、日期、总额；
5. 检查已有有效到账的计划仍存在，且比例和金额未变；
6. 在同一事务中新增、更新计划，并把被删除的未收款计划标记为 `deleted`；
7. 返回保存后的完整有效计划数组。

旧的单期写计划 RPC 对浏览器认证角色撤销执行权，防止旧页面绕过原子校验。实际到账 RPC 增加 `planId` 存在、项目一致性校验；同一计划允许任意多笔到账。

## 界面与草稿

- 标题统一为“收款计划”，按钮为“保存收款计划”，汇总为“计划金额合计”。
- 提供三期、四期、自定义；自定义可增减期次，至少一期。
- 新计划默认三期，比例和金额为空，不套用 30/40/30。
- “平均分配”只在用户主动点击后执行；已有内容将被覆盖或删除前使用确认框。
- 每期采用纵向紧凑卡片：顺序、名称、比例、只读计划金额、约定日期、付款条件/备注和删除按钮；手机端单列且不横向溢出。
- 删除按钮对锁定期次禁用并说明原因；移除内部字段名说明。
- 草稿使用 `sessionStorage`，键包含账号 ID、项目 ID 和表单类型；输入变化即保存。提交失败保留，保存成功或用户确认放弃后清除。

## 验证与发布

- 单元测试覆盖旧三期兼容、三/四/六期、增删、比例错误、取整、锁定保护、到账多笔和草稿隔离。
- React 集成测试覆盖切换/remount、失败重试、成功清除、确认覆盖及响应式结构。
- SQL 测试覆盖权限、原子回滚、总额校验、锁定计划删除/修改拒绝和未收款删除。
- 正式数据库迁移前，定向备份受影响计划、到账、项目/合同变更摘要及旧函数定义，并生成恢复 SQL；在事务回滚演练或隔离数据库中核查恢复脚本。
- 数据库迁移后只做只读线上核查，不创建真实测试记录；正式页面使用现有真实项目做只读兼容验证，写入验证仅使用本地隔离数据库。
