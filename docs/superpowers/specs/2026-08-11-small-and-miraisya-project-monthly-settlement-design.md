# 小项目、未来社项目与月度请求书设计

**日期：** 2026-08-11

**状态：** 用户已确认设计

**适用工程：** `shengwang-erp-h5`

**请求书模板：** `❤️株式会社未来舎サポート請求書(001)_副本.xlsx`

## 1. 目标

在现有工程项目体系中增加两种轻量项目：普通小项目和未来社项目。两种项目都保留独立项目编号，使采购、仓库出库与退料、考勤人工、车辆及其他费用继续通过现有项目成本明细账自动归集。

未来社项目固定客户为“株式会社未来舎サポート”，按完工月份汇总收费、成本与利润。社长或财务部可以生成、确认、作废月度结算，并基于用户提供的 Excel 样本下载可继续编辑的日文请求书。

## 2. 范围与分期

### 阶段一：项目类型与简化项目

- 为现有项目增加主项目、小项目、未来社项目三种类型。
- 在工程项目页面提供三个独立列表和三个创建入口。
- 主项目继续使用现有完整表单。
- 小项目和未来社项目使用简化表单。
- 所有项目继续参与现有项目选择器和项目引用 RPC，确保采购、仓库、考勤、车辆、会计成本无需第二套映射。

### 阶段二：未来社收费与成本利润

- 为未来社项目增加多行对外收费明细。
- 复用现有项目成本明细账，展示人工、材料、车辆、停车及其他费用。
- 计算每个未来社项目的税前收入、税额、含税收入、总成本和毛利。
- 内部成本与对外收费严格分离，不用成本记录自动生成收费项目。

### 阶段三：月度结算与请求书

- 按月份筛选符合条件的未来社项目。
- 生成草稿、确认冻结、作废和重新结算。
- 保存项目、收费、成本与利润快照。
- 基于用户样本生成可编辑 Excel 请求书。

## 3. 项目模型

### 3.1 项目类型

现有 `projects` 记录的 payload 增加 `projectType`：

- `standard`：现有主项目；历史记录缺少该字段时按 `standard` 解释。
- `small`：普通小项目。
- `miraisya`：未来社项目。

三类项目都使用现有 `projectId` 命名空间。不得为轻量项目另外建立无法被现有采购、仓库或考勤模块识别的编号体系。

### 3.2 简化项目字段

小项目和未来社项目保存以下资料：

- 项目名称；
- 客户名称；
- 施工地址及现有定位快照；
- 施工日期；
- 工期类型：半天或全天；
- 负责人；
- 施工人员；
- 预计金额；
- 项目状态与结算状态；
- 备注；
- 现场照片和附件。

未来社项目的客户名称由服务端固定为“株式会社未来舎サポート”，客户端不能用其他值覆盖。照片和附件复用现有项目档案能力，不重复建设文件存储。

普通小项目的预计金额由有权限人员填写。未来社项目的预计金额和实际请求金额均由收费明细自动汇总，表单不得再提供第二个可产生冲突的手工总额。

### 3.3 状态

轻量项目继续复用现有项目状态，同时使用完工日期作为默认结算月份依据。只有已完工且未进入其他有效结算的未来社项目，才可以进入月度结算候选列表。

未完工、资料不完整或本月暂不结算的项目继续保留。具有结算权限的用户可以把未结算项目顺延到后续月份，系统不得静默丢失或重复结算。

## 4. 权限

### 4.1 查看

项目查看继续沿用现有“工程项目查看”权限，不扩大项目和财务数据可见范围。

### 4.2 创建与编辑

以下人员可以创建主项目、小项目和未来社项目，并编辑项目资料及未来社收费明细：

- 社长；
- 后勤部；
- 财务部；
- 设计部；
- 总务部。

权限必须由服务端 RPC 复核，不能只依赖前端隐藏按钮。

### 4.3 删除

只有社长和财务部可以删除项目。已进入确认结算的项目禁止删除；必须先作废相应结算，且仍需满足项目删除规则。

### 4.4 月度结算

只有社长和财务部可以：

- 生成或重新生成月度结算草稿；
- 确认结算；
- 作废结算；
- 下载正式请求书。

## 5. 未来社收费明细

每条收费明细保存：

- 品名；
- 摘要；
- 数量；
- 单位；
- 税前单价；
- 税率；
- 排序号。

税率默认 10%，允许逐条改为 0%。系统使用固定精度金额计算，并派生税前金额、消费税和含税金额。草稿阶段可以保存未完成明细，但确认结算前，每条明细必须具有有效品名、数量、单位、单价和税率。

收费明细是对外收入依据。人工、材料、停车等内部费用来自现有业务模块，不复制为请求书行项目。

## 6. 成本归集与利润

所有新项目继续进入现有项目引用列表，因此：

- 采购可关联具体小项目或未来社项目；
- 仓库项目出库和退料按实际批次成本计入或冲减该项目；
- 考勤与工资核算按项目产生人工费；
- 车辆、停车和其他项目费用按现有来源进入项目成本明细账；
- 会计成本页面继续复用统一项目成本事实。

项目收入分别展示税前收入、消费税和含税收入。毛利使用税前收入减去现有项目成本明细账的权威总成本，不能把含税收入直接用于利润计算。月度页面至少显示各项目税前收入、消费税、含税收入、人工费、材料费、停车/车辆费、其他费用、总成本和毛利。

当成本明细账处于加载、不完整、无权限或错误状态时，可以生成草稿预览，但禁止确认结算，并明确显示缺少的成本来源。

## 7. 月度结算

### 7.1 归属规则

默认按实际完工月份归集。尚未结算的项目可以由有权限人员手动顺延到后续月份。

请求书发票日期使用点击生成当天。请求书编号格式为 `MIRAI-YYYYMM-NNN`，例如 `MIRAI-202608-001`。

### 7.2 草稿

社长或财务部选择月份后，页面列出该月已完工且未结算的未来社项目。用户可以勾选、取消或顺延项目。草稿实时计算收入、消费税、总成本和利润，可重复生成。

### 7.3 确认

确认结算必须由一个服务端事务完成：

1. 校验操作者权限；
2. 锁定并生成月份内唯一连续编号；
3. 锁定候选项目并验证未被其他有效结算使用；
4. 验证项目已完工且收费明细完整；
5. 获取完整项目成本快照；
6. 保存项目资料、收费明细、成本分类、收入、税额和利润快照；
7. 将结算状态改为已确认。

确认后的快照不随项目、收费或成本来源的后续修改而变化。普通编辑不能修改已确认快照。

### 7.4 作废

社长或财务部可以作废结算。作废保留原编号、原快照、操作者、时间和原因作为审计记录，并释放项目供后续重新结算。不得物理删除已确认或已作废结算。

## 8. 请求书 Excel

### 8.1 模板

用户提供的工作簿包含一个 `Sheet2` 工作表、72 行、8 个使用列、87 个公式和固定合并区域。实现以该文件作为模板，保留：

- 字体、字号、边框和对齐；
- 行高、列宽和合并单元格；
- 生旺株式会社资料、登录编号和银行资料；
- 日文表头、金额格式和打印设置；
- 工事分块和底部汇总结构。

### 8.2 自动填充

生成时自动填充：

- 收件方：`株式会社未来舎サポート`；
- 发票日期：点击生成当天，使用模板日文日期格式；
- 请求书编号；
- 对应结算月份的件名；
- 每个项目的地址、施工内容和完成日期；
- 每条收费明细的品名、摘要、数量、单位、单价、税前金额、税额和含税金额；
- 税前小计、消费税和含税合计。

请求书编号显示在首张工作表右上方的空白第 3 行：`G3` 写入“請求書番号：”，`H3` 写入编号；该位置不得改变现有日期、公司或银行信息。

### 8.3 动态行与分页

模板现有五个工事区块不构成数量上限。超过容量时，系统复制同样的工事表头、明细、边框、公式和行高，并自动增加行或分页。分页后的页面继续保持可打印、可阅读的版式。

生成结果必须是普通、可编辑的 `.xlsx`，不得导出为只有图片或锁定内容的工作簿。建议文件名：

`株式会社未来舎サポート_YYYY年MM月_請求書_MIRAI-YYYYMM-NNN.xlsx`

Excel 下载失败不得回滚已保存结算；用户可以从同一快照再次生成和下载。

## 9. 页面设计

### 9.1 工程项目页面

- “新增项目”入口提供新增主项目、新增小项目、新增未来社项目三个选择。
- 页面提供主项目、小项目、未来社项目三个独立列表。
- 主项目保留现有完整表单。
- 小项目和未来社项目使用简化表单。

### 9.2 未来社项目详情

显示项目资料、施工状态、收费明细、含税收入、自动归集成本、毛利、结算状态、照片和附件。收费明细支持新增、编辑、删除和排序。

### 9.3 未来社月度结算页面

页面包含月份选择、候选项目、顺延操作、收入与成本汇总、利润、草稿状态、确认状态、请求书下载和历史结算列表。

## 10. 数据与服务边界

- 项目类型继续保存在受保护的项目 payload 中，并扩展现有项目 RPC 白名单和校验。
- 收费明细使用独立关系表 `miraisya_billing_items`，通过项目 ID 关联未来社项目。
- 月度结算使用主表 `miraisya_monthly_settlements`、项目快照明细表 `miraisya_monthly_settlement_projects` 和收费快照明细表 `miraisya_monthly_settlement_items`；确认与作废只通过安全 RPC。
- 项目引用 RPC 继续返回现有最小字段，必要时增加类型但必须同步更新严格响应校验和所有调用方测试。
- Excel 在浏览器端使用现有 ExcelJS 能力从模板生成；结算快照及编号由服务端负责，客户端不得自行认定正式结算成功。

## 11. 错误与并发处理

- 重复编号：使用数据库事务锁和唯一约束防止。
- 重复结算：项目与有效结算之间设置唯一约束并在事务内锁定。
- 成本不完整：允许草稿，禁止确认，显示具体来源状态。
- 收费明细无效：定位到项目和具体行，禁止确认。
- 项目被并发修改：确认前重新读取并校验版本或更新时间。
- Excel 生成失败：保留结算数据，允许再次下载。
- 已确认记录修改：服务端拒绝，并提示先作废结算。

## 12. 测试与验收

### 12.1 前端与领域测试

- 三种项目类型的默认值、校验、列表分组和历史项目兼容；
- 简化表单、固定未来社客户及半天/全天字段；
- 收费明细的 10% 默认税率、0% 手动税率和固定精度金额；
- 月度筛选、顺延、收入成本利润汇总和状态展示；
- 权限按钮和错误状态。

### 12.2 服务与数据库测试

- 创建、编辑、删除和结算权限矩阵；
- 非未来社项目不能写入未来社收费明细；
- 重复编号、重复结算和并发确认；
- 确认快照冻结、作废审计和重新结算；
- 项目引用、采购、仓库、考勤和成本明细账继续识别新项目类型；
- RLS 与 RPC 不能被客户端绕过。

### 12.3 Excel 验收

- 与样本比较工作表名称、使用范围、合并区域、字体、边框、行高、列宽和打印设置；
- 验证发票日期、公司名称、项目内容和编号替换；
- 验证 0% 与 10% 税行、分项目小计、税前小计、消费税和合计；
- 验证超过五个项目时的扩行与分页；
- 验证无 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或 `#N/A`；
- 使用 Excel/Numbers/WPS 打开确认文件仍可编辑且打印版式一致。

## 13. 非目标

- 本功能不从内部成本自动推导对外报价。
- 本功能不改变现有仓库流水、考勤记录或已冻结成本。
- 本功能不为普通小项目生成未来社请求书。
- 首期不自动发送邮件、不自动上传请求书给未来社，也不自动在月末生成结算。
- 首期不修改用户提供模板中的公司、银行和登录编号资料。

## 14. 成功标准

- 用户能在独立列表中创建和管理小项目、未来社项目。
- 新项目能被采购、仓库、考勤和会计成本模块选择并正确归集。
- 未来社项目能记录独立收费明细并展示真实成本和利润。
- 社长或财务部能按月选择项目、生成草稿、确认冻结和作废结算。
- 系统能按样本格式生成日期自动更新、金额正确、可继续编辑的 Excel 请求书。
- 已确认历史结算在后续项目或成本变化后保持不变且可审计。
