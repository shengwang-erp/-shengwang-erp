# 移除未来舎请求书自动生成功能设计

## 目标

从 ERP 中彻底移除未来舎请求书的 Excel 自动生成与下载能力，今后的请求书由用户在系统外手动制作。

## 保留范围

- 未来舎项目及其简化表单。
- 采购、考勤等成本自动归集。
- 月度结算候选、顺延项目、草稿、确认冻结、解冻和历史记录。
- 月度税前金额、消费税、含税金额、成本和毛利核算。
- 社长与财务部的月度结算权限。

## 删除范围

- 月度结算页面中的“请求书下载”按钮及下载状态处理。
- `App` 中的 Excel 下载接线和结算版本下载校验。
- 未来舎请求书 Excel 生成模块及其专用测试。
- ERP 公开目录中的未来舎 Excel 模板。
- 只为自动请求书功能增加的页面测试断言。

## 不处理范围

- 不删除用户桌面上的原始请求书样表。
- 不删除已经冻结的月度结算数据。
- 不改变月度结算数据库表、RPC、权限与冻结规则。
- 不改变其他模块可能使用的 `exceljs` 依赖。

## 用户界面与数据流

月度结算页面继续显示候选项目、汇总、草稿、冻结、解冻和历史结算。历史卡片不再显示下载按钮。结算数据仍作为会计核算与人工制作请求书的依据，但不会在浏览器中生成文件。

## 错误与安全

删除公开模板后，原模板中的公司银行信息不再能通过 ERP 的静态地址下载。删除下载接线后，系统不会再加载 Excel 组件，也不会出现请求书模板读取、浏览器下载或结算版本下载冲突错误。

## 测试与验收

- 页面源码和 `App` 不再包含请求书下载、`onDownload` 或 `downloadMiraisyaInvoice`。
- 自动生成模块、测试和公开模板均不存在。
- 月度结算相关测试继续通过。
- ERP 全量测试通过。
- 生产构建成功。
- 本地 ERP 的月度结算页面仍能访问，且不再出现请求书下载按钮。
