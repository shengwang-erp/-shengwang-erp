# 黑金业务页面表面一致性设计

## 目标

消除登录后 ERP 业务页面中遗留的白色、浅蓝色和浅灰色卡片，使所有可见业务表面遵循现有黑金设计系统。采购管理当前截图确认旧版 `.form-group` 背景和图例仍覆盖为浅色；同类问题也存在于车辆、工具、人员、人工记录、会计只读字段、工程项目局部说明和今日打卡局部控件。

## 已确认决策

- 采用共享主题集中覆盖方案，不逐页重写组件。
- 卡片使用暖黑或炭黑背景，使用低饱和金色细边框。
- 分组标题和字段标签使用品牌金或浅金；正文和输入值使用暖白色。
- 输入框、下拉框和文本域保持深黑背景，并保留清晰的边界、聚焦环和禁用状态。
- 修改覆盖全部登录后业务页面，同时明确排除登录/认证页、打印样式和仓库标签。

## 方案比较

### 方案 A：共享黑金主题补齐遗漏组件（采用）

在 `src/blackGoldTheme.css` 内使用 `.erp-black-gold` 作用域覆盖遗留浅色表面。该方案沿用现有令牌，不修改页面结构和业务逻辑，改动集中且最容易逐页验证。

### 方案 B：替换旧版全局颜色变量

改动较少，但会影响未纳入黑金后台的认证、打印和状态组件，回归范围不可控，因此不采用。

### 方案 C：逐页面重写样式

可以彻底清理旧 CSS，但会重复规则并扩大改动范围，容易造成页面间漂移，因此本次不采用。

## 视觉规范

- 页面画布继续使用 `--erp-bg-canvas`。
- 一级卡片和面板使用 `--erp-bg-surface`。
- 分组、只读字段、统计内层和次级容器使用 `--erp-bg-elevated`。
- 普通边框使用 `--erp-border-subtle`；需要强调的分组标题或选中状态使用 `--erp-border-gold-muted`。
- 分组标题使用 `--erp-accent-gold-soft`，字段标签使用 `--erp-accent-gold` 或 `--erp-text-secondary`，输入值和金额使用 `--erp-text-primary`。
- 成功、警告、错误和信息状态继续使用现有语义色及对应深色表面，不强行改成金色。
- 不改变现有圆角、间距、布局、字体尺寸和响应式断点，避免视觉修复影响操作习惯。

## 覆盖范围

共享主题至少覆盖以下遗留组件：

- `.form-group` 及其 `legend`。
- `.readonly-field strong`。
- 人员统计、空状态、筛选和资料分组。
- 人工记录的加载面板、设置卡、统计卡和对话框分组。
- 工程项目定位说明、会计只读金额、采购/车辆/工具表单分组。
- 今日打卡的返回按钮和仍使用浅色表面的状态卡。
- 其他经 CSS 扫描或逐页截图确认的登录后浅色业务表面。

页面专用 CSS 可能晚于共享主题注入，因此覆盖规则必须同时具备 `.erp-black-gold` 作用域和足够明确的组件选择器。禁止使用无作用域的全局通配规则，也禁止使用 `!important` 掩盖不明确的层叠关系，除非既有布局规则本身只能用同等优先级覆盖且有测试说明。

## 明确排除

- 登录、重新验证和认证状态页。
- `warehouseLabel.css` 中用于实体标签的白色纸张背景。
- `warehouseReportPrint.css` 中用于打印输出的白色页面背景。
- 浏览器原生日期选择弹层和操作系统控件外观。
- 数据、权限、路由、表单字段、提交逻辑和仓库流程。

## 错误与可访问性

- 深色化后所有字段标签、输入值、占位符和只读金额必须保持可辨认；不能用低对比金色承载长正文。
- 键盘焦点继续使用 `--erp-focus-ring`，不能被新增背景或边框覆盖。
- 禁用状态仍须可识别，不能只靠颜色表达；现有文字和可用性语义保持不变。
- 语义状态保留文字和颜色双重表达。本次只能确认视觉对比风险，完整屏幕阅读器与键盘流程仍依赖既有自动化和交互测试。

## 测试与验收

1. 先扩展 `src/blackGoldTheme.test.js`，为共享表单分组、图例、只读字段和已知页面专用浅色组件增加精确声明断言，并确认测试在样式修改前失败。
2. 样式实现后运行黑金主题测试、相关页面测试、完整测试和生产构建。
3. 使用当前 Chrome 登录态逐页检查全部一级菜单页面，重点核对采购、车辆、工具、人员、会计、人工记录、工程项目和今日打卡。
4. 在桌面宽度检查卡片、图例、标签、输入框、状态色、边框和滚动区域；在手机宽度抽查表单堆叠、底部导航和横向滚动。
5. 保留修改前后相同视口截图进行对比，确认没有白色或浅蓝色业务卡片、文字不可读、布局跳动或误伤打印/认证页面。

## 完成标准

所有登录后业务页面的卡片和表单分组都使用统一黑金层级；采购页面当前可见的浅蓝/白色区域完全消失；已知页面专用浅色泄漏得到覆盖；状态语义、认证页、打印页和标签输出保持原样；自动化测试与生产构建通过；逐页浏览器验收未发现新的浅色业务表面或可读性回退。
