# 会计成本弹窗 Portal 黑金主题修复设计

日期：2026-08-11  
目标分支：`codex/project-cost-dialog-fix`

## 目标

修复会计成本中“新增调整费用”、“调整金额”和“拆分项目”三个弹窗在 Portal 渲染后丢失黑金主题的问题。保留现有字段、权限、校验、保存、审计、焦点管理和关闭行为，只修复弹窗的主题作用域、布局与响应式表现。

## 根因

`DesktopAdminShell` 把 `erp-black-gold` 主题类放在 ERP 应用容器上。三个项目成本弹窗使用 `createPortal` 直接渲染到 `document.body`，因此 Portal 内容不再是 `.erp-black-gold` 的后代。弹窗 CSS 全部使用 `.erp-black-gold .project-cost-*` 选择器，导致遮罩、居中、尺寸、黑金配色和表单网格均未命中。最终表现为白色原生表单出现在页面底部。

## 已确认方案

采用方案 A：让 Portal 的最外层遮罩节点自身携带 `erp-black-gold` 主题类，并将遮罩节点本身的选择器调整为同元素选择器。弹窗内部其余选择器继续使用后代结构，从 Portal 根节点继承现有主题变量。

不采用以下方案：

- 不把 Portal 改挂到 ERP 应用容器，避免遮罩受容器裁切、滚动或层叠上下文影响。
- 不移除黑金主题作用域，避免项目成本弹窗样式污染登录页或其他界面。
- 不在弹窗打开时动态修改 `body` 的全局主题类，避免多弹窗、异常卸载和清理时序问题。

## 界面设计

设计保持现有 ERP 黑金视觉语言，并偏向电脑端高频操作。

- 弹窗在视口水平与垂直方向居中。
- 背景使用深色遮罩与轻度模糊，弹窗保持金色顶边、细金边框、圆角和阴影。
- “新增调整费用”和“调整金额”使用最大 760px 宽度；“拆分项目”使用最大 900px 宽度。
- 标题区、表单区和底部操作区保持清楚间距与层次。
- 新增费用的项目、费用类别、日期、金额和经办人在电脑端使用两列网格；费用说明和录入原因独占整行。
- 表单控件统一为深色背景、黑金边框和可见焦点态。
- 底部右对齐“取消”与金色主按钮；禁用和保存中状态保持现有逻辑。
- 弹窗高度不超过视口；内容过长时只在弹窗内滚动，不会掉到主页面底部。
- 760px 及以下宽度时自动改为单列，并缩小外边距；电脑端是主要验收环境。

## 组件范围

修复同时覆盖：

1. `ProjectCostManualEntryDialog`：新增调整费用；
2. `ProjectCostAdjustmentDialog`：调整金额；
3. `ProjectCostAllocationDialog`：拆分项目。

三个组件的 Portal 根节点使用同一主题契约。不更改 `ProjectCostLedgerSection` 的弹窗打开条件，不更改服务接口或数据结构。

## 交互与错误处理

- 保留 `useProjectCostModalA11y` 提供的初始焦点、Tab 焦点循环、Escape 关闭和关闭后焦点恢复。
- 保留提交期间不可关闭、重复提交防护与授权失效处理。
- 保留现有字段必填、空白、金额精度、拆分平衡和权限校验。
- 错误和无权限提示使用弹窗内既有警告样式，不更改文案与错误映射。

## 测试与验收

自动测试需覆盖：

- 三个弹窗的 Portal 根节点同时具有 `erp-black-gold` 和 `project-cost-dialog-backdrop` 类。
- CSS 使用同元素主题选择器命中 Portal 遮罩，而内部弹窗继续受主题作用域约束。
- 已有表单校验、提交、防重、焦点循环、Escape 关闭、异步期间关闭和 Portal 渲染测试继续通过。
- 黑金主题作用域测试不因修复而放宽为全局样式。

构建后的电脑端浏览器验收项：

1. 从会计成本中打开“新增调整费用”，弹窗在当前视口居中显示，页面背景被遮罩。
2. 弹窗使用黑金配色和双列表单，长文本字段占整行，按钮位于底部。
3. 分别打开“调整金额”和“拆分项目”，两者具有相同主题和遮罩行为。
4. 在较矮视口中弹窗内部可滚动，不增加主页面底部的白色原生表单。
5. 在移动窄屏中表单改为单列且不产生水平溢出。
6. 保存、取消、Escape、焦点循环与权限限制的行为与修复前一致。

## 非目标

- 不改变项目成本数据模型、数据库、API 或导出逻辑。
- 不新增或删除弹窗字段。
- 不重设计会计成本主页面。
- 不修改其他模块的 Portal 或全局主题架构。
