# 项目地址自动定位设计

## 目标

在当前第二版 ERP 的“工程项目”新增或编辑表单中，用户填写日本项目地址并停止输入后，地图自动定位到最匹配的位置。自动定位用于辅助确认施工地点，不会单独保存项目；项目仍在用户提交表单时保存。

## 范围与安全边界

- 仅修改 `/Users/yu/Documents/kaobeierp/warehouse-forward-port` 中现有工程项目地址定位功能。
- 复用现有 `ProjectLocationPicker`、`projectLocationService`、日本国土地理院地图与 Nominatim 地址搜索，不更换地图服务。
- 不修改仓库管理、数据库结构、现有项目记录和线上部署。
- 不操作已归档第一版。
- 保留“地址定位”按钮、地图点击和标记拖动三种人工备用方式。

## 交互设计

1. 用户修改项目地址时，当前地址原有的“已确认”状态按现有规则失效。
2. 用户停止输入约 1.2 秒后，系统自动发起一次定位；空地址不发起请求。
3. 定位中显示现有“定位中…”状态，并避免重复提交定位请求。
4. 成功时采用服务返回的第一个最匹配结果，将地图居中、显示可拖动标记和打卡范围圆圈，并显示服务返回的完整地址供核对。
5. 自动定位得到的坐标只进入当前项目表单；只有用户提交项目表单后才会保存。
6. 用户仍可点击“地址定位”立即重试，也可点击地图或拖动标记修正位置。

## 并发与错误处理

- 地址继续变化、用户点击地图、拖动标记或组件退出时，取消尚未完成的自动定位。
- 只允许最新地址对应的结果更新地图；较早请求即使稍后返回，也不得覆盖新地址或人工选点。
- 未找到结果、网络失败、限流或响应无效时，不移动现有标记、不覆盖现有坐标，并显示现有安全提示。
- 失败提示不暴露地图服务内部错误；用户可以按钮重试或人工选点。
- 继续复用现有缓存和请求间隔控制，避免对公共地址服务发送过多请求。

## 实现边界

- 在定位组件中增加可取消的延迟计时器，并复用同一个定位执行入口处理自动触发和按钮触发。
- 定位成功后保存并展示 `displayName`；地址变化或人工选点时清除旧的识别地址，避免误导。
- 不新增第三方依赖，不改变项目数据模型，不把识别地址写入新的数据库字段。

## 测试与验收

- 先写失败测试，证明停止输入后会自动定位，空地址不会定位，按钮仍可立即定位。
- 验证连续输入只采用最后一次地址结果，旧请求和人工选点不会被迟到响应覆盖。
- 验证成功结果显示完整地址，失败时保留原位置和人工备用操作。
