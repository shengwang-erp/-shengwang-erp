# 权限感知的合同收入运行时全局修复设计

## 背景与根因

SW-008（工程部、中工）登录后会先显示首页，随后进入安全错误页。生产浏览器控制台记录到 `ContractRevenueValidationError: contractAmount必须大于0`，诊断指纹 `65f5ecae` 与该原始错误精确一致。

项目目录会根据权限返回两种数据：有项目完整权限的账号读取完整项目；仅需把项目作为采购、人工、车辆或工具关联项使用的账号，只读取包含项目编号、名称、状态和地址的安全投影。当前 `AuthenticatedApp` 无条件对两种数据执行合同收入快照计算。安全投影不含合同金额，经过旧的项目标准化后被补成 `0`，随后被合同收入校验拒绝，最终导致整个业务界面停止。SW-000 能读取完整项目，因此不触发该错误。

## 目标

- 所有无合同财务查看权限的有效账号均可正常进入首页和其获授权的业务页面。
- 无权限账号不读取、不推导、不显示合同金额、收款金额或利润数据。
- 有合同财务权限的账号继续使用现有严格校验；真实的合同数据错误不得被静默吞掉。
- 不修改数据库、不补写合同金额、不调整任何部门或职位权限。

## 方案

在 `AuthenticatedApp` 的共享合同收入派生入口增加权限门：仅当 `contractRevenueAccess.view` 为真时，才调用 `buildProjectRevenueSnapshotCollection`；否则返回空快照集合。后续 `buildProjectRevenueReadModel` 在没有快照时只复制当前已授权的项目字段，因此安全投影保持安全，也不会触发合同计算。

该门位于登录后所有页面共用的数据派生层，而不是只针对 SW-008、iPhone 或首页做特例，因此对所有部门、职位、账号和终端统一生效。合同收入领域函数自身仍保持严格校验，避免有权限用户的坏账务数据被掩盖。

## 数据与权限边界

1. 项目目录按现有权限规则读取完整项目或安全投影。
2. 合同财务权限为真：完整项目进入合同收入快照计算，结果用于合同和财务界面。
3. 合同财务权限为假：不启动合同收入读取与计算，项目安全投影原样进入非财务业务界面。
4. 权限变化或账号切换时，React 依赖项重新计算，旧账号的合同快照不得残留给新账号。

## 错误处理

- 无权限且字段被隐藏是正常状态，不产生错误。
- 有权限但合同数据非法仍抛出领域校验错误，并由现有安全错误页提供不泄密诊断。
- 不通过 `catch` 忽略所有异常，也不把非法合同金额强制当作零，以免隐藏真实财务问题。

## 测试与验收

- 先添加会失败的回归测试，证明只有项目安全投影、且无合同财务权限时不会调用合同收入快照构造器，首页能够渲染。
- 验证安全投影的输出不新增 `contractAmount`、`paidAmount`、利润或合同快照字段。
- 验证有合同财务权限时仍调用原快照构造器，非法完整合同数据仍被拒绝。
- 验证权限或账号切换后不会复用旧合同快照。
- 运行相关测试、全量 `npm test`、生产构建及部署后在线 HTTP/资源版本检查。

## 非目标

- 不修订项目合同金额或迁移线上数据。
- 不改变 SW-008 或其他账号的权限配置。
- 不重构合同收入领域模型，也不修改安全错误页样式。
