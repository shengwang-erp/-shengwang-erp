# 黑金 ERP 统一视觉与老板驾驶舱升级设计

## 目标

将登录后的 ERP 后台统一为参考图所示的深黑金色经营管理系统，消除当前黑金导航、蓝色首页和白色业务卡片并存的割裂感；同时把老板驾驶舱升级为使用真实业务数据的经营分析中心，让社长和会计能够直接查看项目回款、成本、利润、现金流及业务异常。

本次改版必须满足以下原则：

- 项目、人员、采购、会计、人工、仓库、车辆、工具和系统设置使用同一套视觉语言。
- 老板驾驶舱优先展示财务经营信息，下半部分展示本月运营状态和异常。
- 所有指标和图表只使用系统现有数据；没有数据时显示零值或空状态，不生成演示数据。
- 不改变既有业务权限，不因视觉改版放宽敏感数据访问。
- 桌面端保持高信息密度，手机端使用适合触控的工作台和底部导航。

## 已确认的产品决策

1. 登录后的整个后台采用深黑金主题，包括首页、老板驾驶舱及所有业务页面。
2. 驾驶舱采用“财务经营优先、运营异常补充”的信息结构。
3. 财务趋势默认展示以所选月份为终点的最近 12 个月；出勤、采购发生/付款、车辆和月度业务异常展示所选月份；采购数据健康异常与当前应付属于全期间当前快照。
4. 手机端固定底部导航为“首页、工作台、消息、我的”，所有业务入口收纳到工作台宫格。
5. 金色用于品牌、选中状态、关键金额和主要操作；绿色表示正常或收入，红色/橙色表示风险或支出，低饱和蓝色仅表示普通信息。
6. 图表采用轻量原生 SVG，不引入大型图表库。

## 方案比较

### 方案 A：只更换颜色并保留现有页面结构

改动小，但老板驾驶舱仍然以普通统计卡和表格为主，无法达到参考图的经营分析效果，也难以形成可复用的后台视觉规范，因此不采用。

### 方案 B：统一设计系统并重构驾驶舱（采用）

建立独立的黑金主题层，将后台框架、基础控件、表格和业务容器统一；驾驶舱使用共享数据模型和原生 SVG 图表重新编排。该方案可以在不重写业务页面的前提下获得一致视觉，并能保证会计中心与驾驶舱共用相同数据口径。

### 方案 C：整体替换 UI 框架并引入完整图表平台

组件能力最丰富，但会大面积重写现有页面并增加依赖、包体积和回归风险，当前阶段不采用。

## 视觉设计系统

### 色彩与层级

- 页面底色使用接近黑色的暖色背景，避免纯黑造成层级丢失。
- 一级容器、二级卡片和悬浮层使用三个可区分的炭黑层级，并用低对比金色描边分隔。
- 品牌金和高亮金只用于重要层级；普通正文使用暖白色，说明文字使用灰米色。
- 收入、正常、已完成使用绿色；支出、风险、逾期分别使用红色或橙色；信息提示使用低饱和蓝色。
- 图表颜色遵循相同语义，不能为了装饰随意改变同一指标的颜色。

首版令牌固定为：页面背景 `#080806`，一级表面 `#0f0f0d`，二级表面 `#171612`，悬浮表面 `#211f18`，边框 `#3a3120`，品牌金 `#d6aa5c`，高亮金 `#f0c56d`，正文 `#f4efe4`，次要文字 `#9c9485`，正常绿 `#63b36a`，风险红 `#e05c46`，警告橙 `#d98a3d`，信息蓝 `#6d94bd`。实现时只允许为满足对比度在同一色相内微调，并统一回写令牌，不能在页面中散落临时颜色。

### 基础组件

按钮、输入框、下拉框、日期选择器、复选框、弹窗、筛选栏、分页、状态标签、空状态和加载状态统一使用黑金组件样式。焦点、悬停、按下、禁用和错误状态必须清晰可辨，表单仍保留足够对比度和输入边界。

表格采用深色表头、紧凑行高、柔和分隔线和悬停高亮。较长表格保留固定表头；手机端允许横向滚动，不能压缩到无法识别字段。

### 后台框架

桌面端保留左侧导航和顶部栏：左侧显示品牌、业务入口和当前账号，顶部显示当前位置、搜索/通知区域和账号菜单。当前菜单使用金色底纹与左侧强调线，不再使用蓝色激活态。

手机端隐藏桌面侧栏，固定底部四项导航：

- 首页：移动经营概览。
- 工作台：项目、人员、会计、人工、仓库、采购、车辆、工具等业务宫格。
- 消息：异常、待确认和提醒聚合。
- 我的：账号信息、权限可见范围与退出登录。

主题样式放入独立文件并限定在登录后台根容器内，以覆盖现有视觉但不侵入登录页，也不覆盖业务页面已有的局部功能规则。桌面布局以 `1024px` 及以上为主，窄于 `768px` 时切换到移动底部导航；中间宽度使用可换行的紧凑布局。

## 老板驾驶舱信息结构

### 页头与全局筛选

页头显示欢迎语、当前日期、数据范围说明、项目选择器和月份选择器。默认项目为“全部项目”，默认月份为当前月份。项目和月份改变后，页面所有可筛选的指标、图表、异常及明细同步更新。

财务趋势固定展示以所选月份为终点的连续 12 个月；本月运营组件使用所选自然月。项目数量、项目状态、合同、累计收款、当前应收及累计利润属于当前经营快照，月份选择器不伪造历史快照。所有卡片必须显示自身口径，例如“当前有效项目”“当前累计”“2026 年 7 月”或“最近 12 个月”，避免把当前值、累计值和月度值混淆。

### 第一层：经营关键指标

顶部使用五张紧凑指标卡：

1. 项目总数及在建项目数。
2. 合同总额。
3. 累计已收款。
4. 累计未收款。
5. 预计利润及预计利润率。

指标卡显示主值和口径说明。当前项目数、当前合同额、累计收款、当前应收及累计利润没有历史版本快照，不显示环比；只有具备连续月度事实的收款、成本和已记录现金支出才显示上月差额，前月大于零时才显示环比百分比。

### 第二层：核心财务图表

- **项目收款进度环形图**：已收款与未收款构成，并显示整体回款率。
- **项目状态柱状图**：严格按项目主数据中的报价中、设计中、待开工、进行中、暂停、已完工和已取消七个互斥状态统计。收款状态另行展示，不能与生命周期状态混在同一组重复计数。
- **待办与异常面板**：人工打卡异常、待确认人工记录、采购异常、采购应付、未绑定项目数据、车辆异常和其他需核对事项。每项可跳转到有权限访问的对应业务页面。
- **最近 12 个月已记录现金趋势图**：按月展示实际项目收款、具备付款依据的已记录支出和已记录净现金流，并常驻显示覆盖范围说明。
- **成本构成图**：展示人工、采购、车辆、其他项目成本和公司经营费用的构成；待核对手工成本另列警示值，不混入已确认构成。
- **项目盈利排行图**：按预计利润或利润率展示项目排名，并同时提供合同额、累计成本和利润数值。

### 第三层：所选月份运营分析

- 人员出勤状态、打卡异常数量和当月人工费用。
- 采购确认成本、实际付款、当前应付余额和采购数据异常。
- 车辆当月费用、使用状态和异常提醒。
- 仓库库存与工具借用使用简洁状态指标呈现；没有有意义时间序列的数据不强行绘制图表。

### 第四层：项目经营明细

保留可查询的项目经营表格，展示项目名称、状态、合同额、已收款、未收款、人工费、采购费、车辆费、其他确认成本、待核对手工成本、确认总成本、预计利润和利润率。表格支持项目筛选、状态筛选、排序及进入项目详情。

## 权威数据口径

### 合同、收款与利润

- 项目数量和状态以当前有效项目主数据为准，删除记录不计入。
- 面向客户的合同、已收和未收金额使用合同收入读模型的含税字段：`adjustedTaxInclusiveAmount`、`totalReceivedTaxInclusiveAmount` 和 `outstandingTaxInclusiveAmount`。
- 现金收入趋势只使用未作废、未删除的项目收款流水，以 `receivedDate` 归月、`taxInclusiveAmount` 计额；不能用项目缓存金额反推月度收款。
- 利润收入必须使用现有权威的税抜锚点 `profitAnchorTaxExclusiveAmount`，绝不能用含税合同额减成本。锚点缺失或无效时，该项目利润显示“待完成合同收入确认”并进入异常，不按零利润替代；`allocationStatus = legacy_compatibility` 的旧项目可沿用兼容锚点，但必须显示“历史税额未拆分”，不能称为已审核税抜收入。
- 当前预计利润为税抜利润锚点减当前累计已确认项目成本；利润率仅在税抜锚点大于零时计算。
- 含税累计收款超过含税合同额时，未收款显示为零，超收金额进入数据健康提示。

### 成本事实优先级

驾驶舱与会计成本中心改为共用同一成本聚合函数。各类成本按以下优先级统计，不能在展示组件中重新相加：

| 成本类别 | 权威事实 | 项目归集 | 手工补录处理 |
| --- | --- | --- | --- |
| 人工 | 正式人工核算桥接的月工资总额、项目月度及项目累计分摊；启用日前才使用现有兼容人工/工资记录 | 项目利润使用项目累计人工分摊，公司月成本只使用工资总额，二者是分配关系而非两份公司成本 | `projectCostRecords.costType = 人工费` 不进入已确认成本，列入“待核对手工成本”；外部劳务应改为“外包费” |
| 采购 | 共享采购会计读模型中的有效采购单 `totalCost` | 仅 `projectId` 明确的项目采购进入对应项目 | `材料费`、`工具费` 不进入已确认成本，列入待核对；需要成本时应在采购管理登记 |
| 车辆 | 加油 `fuelAmount` 和车辆费用 `amount`；车辆异常中的 `repairCost` 因没有付款/费用关联字段，仅作为待核对维修估算 | 仅 `allocateToProject = true` 且项目有效的正式费用进入项目；公司总成本仍只计每条车辆事实一次 | `车辆费` 不进入已确认成本，列入待核对；实际维修应在车辆费用中登记，避免同时使用异常维修估算重复计费 |
| 其他项目成本 | 手工项目成本中的 `外包费`、`运输费`、`其他费用` | 按记录 `projectId` 归集 | 作为明确的补充成本计入一次 |
| 经营费用 | 经营费用记录 `amount` | `allocateToProject = true` 时进入该项目利润；无项目时只属于公司 | 同一记录在公司总成本只计一次，项目归集只是分配视图 |

手工 `人工费/材料费/工具费/车辆费` 的金额必须单独展示为“待核对手工成本”，不静默丢失，也不进入已确认成本和预计利润。会计完成归类或转录到权威模块后，异常消失。该规则用于消除当前人工、采购、车辆正式事实与手工项目成本可能重复相加的问题。

项目累计已确认成本为：项目累计人工分摊 + 项目采购确认成本 + 项目车辆正式费用 + 可计入的其他项目成本 + 分摊到项目的经营费用。公司月度权责成本为：月工资总额 + 月采购确认成本 + 月车辆正式费用 + 可计入的月手工项目成本 + 月经营费用；项目人工分摊不得再次增加公司总成本。库存金额属于资产状态展示，不重复作为成本加入。

### 采购一致性

采购统计继续复用会计成本中心的共享采购会计读模型：采购单形成权责采购成本，采购付款流水形成现金支出。付款不能再次增加项目成本。当前应付余额和孤儿付款、重复付款、作废采购关联付款、超额付款、缓存差异、缺少项目等健康异常均为全期间当前快照，不随历史月份选择器改变，并必须明确标注“当前”。

### 已记录现金流

现有数据并非所有成本都有付款日期，因此图表命名为“已记录现金流”，不能宣称为完整银行现金流。逐类规则如下：

现金资格必须在兼容默认值写入之前判断。采购付款、加油和车辆费用从原始持久化记录生成来源标记，例如 `hasRecordedPaymentDate`、`hasRecordedExpenseDate`、`hasRecordedPaymentMethod` 及对应 `dateSource = recorded | defaulted`。兼容层补成今天或“现金”的值只能用于表单显示，`defaulted` 永远不能取得现金资格；新建/编辑表单实际保存日期和付款方式时才标记为 `recorded`。集合更新不得因为重新标准化未修改旧记录而把 `defaulted` 升级为 `recorded`。已经持久化且确实带日期的旧记录只能按现有记录日期处理，并在现金流覆盖说明中披露历史默认值无法反向识别的限制。

- 收入：有效项目收款的 `receivedDate` + `taxInclusiveAmount`。
- 采购支出：有效采购付款流水的 `paymentDate` + `jpyAmount`。没有付款日期的历史初始已付金额不进入月度现金流，并显示覆盖缺口。
- 经营费用记录只有发生 `date` 和 `amount`，没有付款状态或付款流水；计入权责成本，但本期不进入现金流。
- 车辆支出：加油和普通车辆费用同时记录日期、金额与 `paymentMethod`，本期明确采用“保存即已支付”的代理规则，分别以 `fuelDate + fuelAmount`、`expenseDate + amount` 进入已记录现金流，并在图例标注为车辆即时支出。只有异常发生日期、没有付款方式的 `repairCost` 不进入现金流。
- 工资记录只有 `salaryMonth`/`createdAt`，没有可靠付款日期；工资计入权责成本，但本期不进入现金流，图表固定显示“工资付款日期尚未记录”的覆盖说明。
- 手工项目成本只有发生日期，没有付款状态；计入权责成本的合格补充记录也不进入现金流。

月度已记录净现金流等于上述已记录收入减上述已记录支出。缺少付款日期只影响现金流，不得把对应采购权责成本、人工权责成本、当前应付一并排除，也不得从“待核对维修估算”中隐藏车辆异常金额。

### 时间与筛选矩阵

“最近 12 个月”包含所选月份及之前 11 个完整自然月。没有记录的月份填零以保持时间轴连续，但不生成业务记录。各组件按下表响应筛选：

| 指标或组件 | 项目筛选 | 月份筛选 | 固定口径 |
| --- | --- | --- | --- |
| 项目数、项目状态、含税合同额、累计已收、当前未收 | 是 | 否 | 当前经营快照 |
| 税抜利润锚点、累计成本、预计利润、项目盈利排行 | 是 | 否 | 当前累计快照 |
| 收款进度环形图、项目经营明细 | 是 | 否 | 当前累计快照 |
| 已记录现金流趋势 | 是；项目视图只保留明确归属项目的收支 | 是 | 以所选月为终点的 12 个月 |
| 成本构成图 | 是 | 是 | 以所选月为终点的 12 个月权责成本 |
| 出勤、人工月度状态 | 是；仅项目分摊部分 | 是 | 所选自然月 |
| 采购确认成本、采购实际付款 | 是 | 是 | 所选自然月 |
| 当前采购应付、采购健康异常 | 是 | 否 | 全期间当前快照 |
| 车辆月度费用与业务异常 | 是 | 是 | 所选自然月 |
| 库存与工具状态 | 按已有项目关联能力 | 否 | 当前状态快照 |

项目筛选时，公司级工资、未分配人工和未分配经营费用不伪装成项目成本；它们只在“全部项目/公司”视图中出现。金额计算先转换为有限、安全、非负的整数日元，非法金额或关键字段缺失的数据不进入相应合计并报告异常。

## 组件与数据流

### 主题层

新增独立黑金主题样式文件，由应用入口在现有样式之后加载。后台框架根节点增加主题作用域类，桌面侧栏、顶部栏和移动导航在同一框架组件中响应式切换。业务页面的表单流程保持不变；入口、路由和敏感组件统一接入同一权限映射，修复当前仅隐藏菜单但直接切换页面仍可渲染的缺口。

### 驾驶舱领域层

新增纯函数领域模块，接收已经过权限投影的项目、项目收款、人工、工资、项目成本、经营费用、采购单、采购付款、车辆费用、库存、工具及异常数据，输出：

- 筛选后的经营 KPI。
- 连续 12 个月现金趋势序列。
- 项目状态、成本构成和运营状态序列。
- 项目盈利排行与经营明细行。
- 带类型、严重度、目标页面和关联记录的异常列表。

聚合逻辑与 React 展示分离，保证同一输入始终产生同一结果，并便于单元测试核对金额。

每个数据源不是裸数组，而是 `{ status, data, error, stale, updatedAt }`：`status` 只允许 `loading`、`ready`、`error` 或 `forbidden`。只有 `ready + []` 可以显示真实零值；加载、无权限和失败不能折算成零。现有持久状态钩子的第三个云端状态必须保留并传入；项目收入另建独立加载状态，不能继续用 `[]` 同时表示无权限、未加载和失败。

12 个月人工成本按月读取现有安全人工核算桥接并缓存结果；任何月份缺失时成本趋势显示不完整提示，不能把缺失月当作零。项目当前累计人工使用桥接返回的 `projectLaborLifetimeById`。采购继续直接复用共享采购会计读模型。统一成本聚合函数同时供会计月度汇总和驾驶舱使用，避免两处公式漂移。

### 展示层

驾驶舱拆分为页头筛选、指标卡、图表卡、异常列表和项目明细表。折线图、柱状图、横向排行图和环形图使用共享 SVG 基础组件，并提供文本图例、格式化金额、悬停/键盘提示和无数据状态。

应用数据仍通过现有页面入口加载；补充把 `projectReceipts`、带原始日期来源标记的付款/车辆记录、经营费用、权限掩码及逐源加载状态明确传给驾驶舱。驾驶舱只读业务数据，不在图表组件中修改原始记录。任何未授权的数据源在进入领域层之前就标记为 `forbidden` 且不携带记录，不能只在渲染完成后用 CSS 隐藏。

## 交互、异常与权限

- 页面初次加载显示与卡片结构一致的加载占位，避免大面积跳动。
- 独立可选数据源失败时，依赖该源的卡片显示错误说明，其余已完整加载的卡片继续显示；任何合计所需源不完整时整张合计卡停止计算，不能显示部分总额。
- 身份失效、云端未配置或核心业务访问被安全策略阻断时继续沿用全局失败关闭，不为了保留图表而降低安全级别。服务端允许继续的单源超时可显示旧值，但必须标记“数据可能已过期”。
- 异常列表提供业务名称、问题原因、金额/数量和处理入口；没有目标页权限时只显示信息，不暴露链接或敏感明细。
- 关键筛选保留在页面顶部，在窄屏下折叠为两行而不遮挡内容。
- 图表颜色不是唯一的信息载体，状态同时使用文字、图例或数值表达。
- SVG 图表提供 `role="img"`、可读标题和摘要；键盘焦点、按钮和输入框满足清晰可见要求。
- 大数据量的项目明细优先使用排序、筛选和分页，不一次渲染不可控数量的图形节点。

### 权限矩阵

所有权限继续使用现有 `effectivePermissionKeys` 和最高管理员规则。下表每一行都隐含要求驾驶舱路由权限；任何金额或身份信息还要求 `sensitive.owner_dashboard_full_view`。`查看老板驾驶舱全部数据` 是额外总闸，不替代项目财务白名单、目标业务模块或具体敏感权限。

| 区域 | 必须权限 |
| --- | --- |
| 驾驶舱路由与页面壳 | `module.owner_dashboard.view`；直接切换路由也必须二次校验 |
| 项目数量与生命周期状态 | 上述权限 + `module.projects.view` |
| 合同、收款、应收和收款图表 | 上述权限 + `sensitive.owner_dashboard_full_view` + `canViewProjectFinancials(currentUser)` + `sensitive.contract_amount_view` |
| 税抜利润、成本、利润排行和利润列 | 合同权限全部满足，再加 `sensitive.profit_view`；任何被隐藏成本分项都不能通过总额反推出 |
| 人工出勤和待确认数量 | `module.labor.view`；工资或人工金额另需 `module.salaries.view`、`sensitive.salary_view` 和人工桥接要求的 `module.project_costs.view` |
| 采购确认成本 | `module.purchases.view`；采购付款、当前应付和付款异常另需 `sensitive.purchase_payments_view` |
| 车辆、库存、工具状态 | 分别需要 `module.vehicles.view`、`module.inventory.view`、`module.tools.view` |
| 人员数量 | `module.employees.view`；在留/身份提醒另需 `sensitive.employee_identity_view` |
| 会计成本各页签 | 页面壳需 `module.accounting.view`；工资、项目成本、经营费用、采购对账继续叠加各自模块和敏感查看/修改权限 |

成本构成图按人工、采购、车辆、项目补充成本和经营费用分别应用源模块权限；任一分项不可见时，不展示可由减法反推出该分项的总成本。侧栏、桌面首页、移动工作台、移动消息、异常处理链接和最终页面渲染共同使用一份路由权限表，不能各自写一套条件。移动“首页”对没有驾驶舱敏感权限的普通员工只显示其获准模块的非敏感工作概览；“消息”只返回用户有权查看的异常内容和数量。

## 实施边界与顺序

本次会统一所有后台页面的视觉外壳和基础控件，但不重写各业务模块的表单流程。为保证驾驶舱可信，本次同时完成共享成本口径、逐源加载状态、页面级权限守卫以及会计/采购页签与按钮的现有权限对齐；不新增工资付款流水、经营费用付款流水等数据库业务模块。因缺少付款事实而无法进入现金流的记录只做覆盖提示，不猜测付款日。

实施顺序为：

1. 建立主题令牌、统一路由权限表和后台框架响应式结构。
2. 建立共享成本聚合、驾驶舱纯函数数据模型及测试。
3. 接入逐源加载状态、12 个月人工核算窗口及权限投影。
4. 实现共享 SVG 图表和驾驶舱布局。
5. 将其余业务页面纳入统一主题并修复局部可读性问题。
6. 完成自动化回归、生产构建以及桌面端和手机端浏览器验收。

## 测试与验收

### 数据单元测试

至少覆盖以下场景：

- 所选月份及之前 11 个月的边界正确，跨年月份顺序连续。
- 七月采购、八月付款分别进入七月权责成本和八月现金支出。
- 采购付款不会重复增加项目成本。
- 合同/收款使用含税口径，利润只使用 `profitAnchorTaxExclusiveAmount`；旧兼容项目显示税额未拆分提示。
- 正式人工、采购和车辆事实不会与手工人工费、材料费、工具费或车辆费重复；待核对手工金额保持可见但不进入确认总额。
- 车辆异常 `repairCost` 不会与车辆正式维修费用重复计入确认成本。
- 工资、人工分摊、经营费用、手工成本和车辆异常维修不会因为只有发生日期就进入已记录现金流；车辆即时支出明确按代理规则进入。
- 原始缺日期/付款方式记录经过现有标准化与集合更新后仍保持 `defaulted` 来源，不能因自动补成今天或“现金”而进入现金流；新表单明确保存后才取得 `recorded` 来源。

- 项目生命周期状态七类互斥，付款状态不会混入生命周期柱状图。
- 作废、重复、孤儿、非法金额、缺少项目或日期的数据不会污染对应合计；缺付款日期只排除现金流。
- 超合同收款不会产生负未收款，并进入异常提示。
- 无记录月份补零，无业务数据时返回稳定空模型。
